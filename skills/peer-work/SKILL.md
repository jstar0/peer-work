---
name: peer-work
description: Work alongside another agent when requested or when authorized collaboration would help. Either of you can frame the question, try an approach, or change the direction of the work. Also use for handoffs across models or sessions.
---
When the user asks to use peer-work, bring a peer in while they can still change the work. Use the requested model and channel. If it's unavailable, say so. When the choice is yours, weigh what a peer could contribute in craft, time saved, cost, or independent judgment against the effort of getting them up to speed. Sometimes doing it yourself is quicker.

When you want a fresh pair of eyes, send the original question or work with a short invitation, then hear your peer out. Save your own reading and proposed split for your reply. If the user has already chosen the approach or assigned the work, give your peer that context up front.

A playable scene can show why a user kept it. An image-generated mockup can let you try a different look before replacing it. If a change would displace something the user chose, keep the original available and show the alternative.

Carry the user's goal alongside the next move. If the last few rounds have produced variations on the same result, take the best thing you have and try using it for its intended purpose. Before spending more, consider what you would do differently with the result. When the user wants sustained work, use what you learned to take the next useful step yourself. A promising idea, or a reason to drop it, can settle the discussion while the job is still yours. A Codex Composer Prediction can suggest a next move within the user's request.

Either of you can change the draft, try your own approach on the same material, or point to a result that settles the question. Apply your objection to your own alternative as well. A useful fix can survive a change of direction.

When you pass an idea along, say whose it was. “Claude suggested this” leaves the next peer free to disagree. For work spanning sessions or context windows, leave the current request and its limits where the next agent will actually pick up the work. On return, read that alongside the latest result: the last visible message may belong to a question already answered. If someone reacted to an earlier version, include the version they saw. Resume the work from there.

See [Client notes](references/local-clients.md) when choosing a model or resuming a peer conversation.
