---
name: peer-work
description: Work alongside another agent when requested, when authorized collaboration would help, or when handing work across models or sessions. Either peer can shape the approach.
---
When the user asks for peer-work, bring a peer in while they can still change the work. Use the requested model and channel. Start the peer with the user's usual permissions for this work so they can decide what to inspect or try. If the requested setup is unavailable, say so. When the choice is yours, weigh the peer's craft, perspective, cost, and time saved against the effort of bringing them up to speed. Sometimes doing it yourself is quicker.

Invite peers into the question you still need to answer together. When the user's own words already ask it, pass them on as written. Add only context the peer is missing, such as the original work or a decision the user made. Leave the approach and the shape of the reply to the peer. For independent views, start fresh if the conversation or shared files would reveal someone's answer before the others form their own.

As promising leads emerge, decide together whether to follow them separately. When a finding could change what another peer tries next, bring it to them while the choice is open. A rough draft, a counterexample, or an unfinished idea can be enough to work on together.

Pick a promising idea and try it on the user's actual problem. If you're using a sample to understand a system, read the output itself and use it to answer the question you ran the trial for. If the result leaves that question open, choose what to try next and say why. Once a direction holds up, carry it through and check the result. Before replacing something the user chose, experience the original and keep it available alongside the alternative.

The agent talking to the user owns the decision and the delivery. Keep the user's words distinct from what either of you proposed. If a peer read the request differently, return to the source together while their reasoning can still change your mind. Make the choices the user entrusted to you. Where their taste or firsthand knowledge would change the direction, bring your best idea while they can still steer. An existing example or a small sketch may be enough. Give your recommendation and any peer reasoning that could change the choice in the same reply.

Across sessions, leave the user's request and its limits with the current work where the next agent will pick them up. If someone reacted to an earlier version, say whose reaction it was and what they saw. Check whether a later exchange settled the question before picking it up again.

See [Client notes](references/local-clients.md) when choosing, contacting, or resuming a peer.
